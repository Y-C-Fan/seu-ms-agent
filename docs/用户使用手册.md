## 1. 快速入门

### 1.1 五分钟快速体验

```bash
# 1. 确保已安装（参考安装指南）
cd seu-ms-agent

# 2. 配置API Key
export OPENAI_API_KEY="your-key-here"

# 3. 运行第一个任务
python3 orchestrator/main.py "Build a simple calculator"
```

### 1.2 工作流程概览

```
你的需求 → Research (研究) → Spec (规范) → Test (测试) → Code (代码) → 验证 → 交付
             ↓               ↓               ↓
         人工审查        人工审查         自动验证
```

### 1.3 核心概念

| 概念 | 说明 | 示例 |
|-----|------|------|
| **Query** | 自然语言需求描述 | "Build a REST API for todo management" |
| **Research** | 自动搜索和分析相关技术 | 搜索REST API最佳实践 |
| **Spec** | 技术规范文档 | API定义、数据模型、架构设计 |
| **Test** | 测试用例 | pytest测试套件 |
| **Code** | 实现代码 | Python源代码 |
| **Workspace** | 工作区 | workspace/run_xxx/ |

## 2. 基本使用

### 2.1 基本命令格式

```bash
python3 orchestrator/main.py <需求描述> [选项]
```

### 2.2 使用模式

#### 2.2.1 仅研究模式

**适用场景**: 只需要技术调研，不生成代码

```bash
python3 orchestrator/main.py \
  "What are the best practices for REST API design?" \
  --mode research_only
```

**输出**: `workspace/run_xxx/report.md`

**用途**:
- 技术调研
- 学习新技术
- 准备技术方案

#### 2.2.2 完整模式（默认）

**适用场景**: 从需求到代码的完整流程

```bash
python3 orchestrator/main.py \
  "Build a calculator with basic operations" \
  --mode full
```

**输出**:
- `report.md` - 研究报告
- `tech_spec.md` - 技术规范
- `tests/` - 测试用例
- `src/` - 源代码

### 2.3 输入方式

#### 2.3.1 纯文本需求

```bash
python3 orchestrator/main.py \
  "Create a command-line tool to convert JSON to YAML"
```

#### 2.3.2 基于文档生成

```bash
python3 orchestrator/main.py \
  "Implement the algorithm described in this paper" \
  --files ./algorithm_paper.pdf
```

#### 2.3.3 基于在线资源

```bash
python3 orchestrator/main.py \
  "Build a web scraper following this tutorial" \
  --urls https://example.com/tutorial.html
```

#### 2.3.4 混合输入

```bash
python3 orchestrator/main.py \
  "Implement a recommendation system" \
  --files ./requirements.docx \
  --urls https://arxiv.org/paper/recommendations
```

## 3. 高级功能

### 3.1 Human-in-the-Loop交互

#### 3.1.1 审查时机

系统会在以下节点暂停，等待你的审查：

1. **Research完成后**: 审查研究报告
2. **Spec完成后**: 审查技术规范

#### 3.1.2 交互选项

```
🛑 [Human Review Required]
📄 File: /workspace/run_xxx/tech_spec.md
💡 请检查生成的技术规格书，确保API定义正确。

选项 Options:
  [C]ontinue : 确认内容无误 (或已保存修改)，继续执行
  [R]eload   : 重新读取文件内容并打印预览 (检查修改是否生效)
  [E]xit     : 终止任务

Your choice [C/R/E]:
```

#### 3.1.3 修改建议

**如何修改文件**:

```bash
# 在另一个终端打开文件
code workspace/run_xxx/tech_spec.md
# 或
vim workspace/run_xxx/tech_spec.md

# 修改内容，保存后回到原终端输入 C 继续
```

**常见修改场景**:
- 调整API端点路径
- 修改数据模型字段
- 增加错误处理策略
- 调整技术选型

### 3.2 自定义配置

#### 3.2.1 临时配置（命令行）

```bash
# 设置最大重试次数
python3 orchestrator/main.py "query" --max-retries 5

# 指定工作区路径
python3 orchestrator/main.py "query" --workspace /custom/path

# 跳过人工审查
python3 orchestrator/main.py "query" --no-human-review

# 设置日志级别
python3 orchestrator/main.py "query" --log-level DEBUG
```

#### 3.2.2 永久配置（配置文件）

创建 `custom_config.yaml`:

```yaml
orchestrator:
  max_retries: 5
  workspace_root: "./my_workspace"
  
llm:
  model: "gpt-4o"
  temperature: 0.3
  max_tokens: 4096

research:
  search_engine: "exa"
  max_results: 10

spec:
  validation: true
  human_review: true

test:
  include_fixtures: true
  include_mocks: true

code:
  timeout: 600
```

**使用自定义配置**:

```bash
python3 orchestrator/main.py "query" --config custom_config.yaml
```

### 3.3 批量处理

#### 3.3.1 批量任务脚本

创建 `batch_tasks.txt`:

```
Build a calculator
Create a JSON to YAML converter
Implement a simple web server
```

**批量运行**:

```bash
#!/bin/bash
while IFS= read -r task; do
  python3 orchestrator/main.py "$task" --mode full --no-human-review
done < batch_tasks.txt
```

#### 3.3.2 并行处理（高级）

```bash
# 使用 GNU parallel
parallel -j 4 python3 orchestrator/main.py "{}" --mode full < batch_tasks.txt
```

## 5. 命令参考

### 5.1 必需参数

```bash
python3 orchestrator/main.py <query>
```

| 参数 | 类型 | 说明 | 示例 |
|-----|------|------|------|
| `query` | string | 自然语言需求描述 | "Build a calculator" |

### 5.2 可选参数

```bash
python3 orchestrator/main.py <query> [OPTIONS]
```

| 选项 | 简写 | 类型 | 默认值 | 说明 |
|-----|------|------|--------|------|
| `--files` | `-f` | list[path] | None | 附件文件路径列表 |
| `--urls` | `-u` | list[url] | None | 在线资源URL列表 |
| `--mode` | `-m` | choice | full | 运行模式: research_only \| full |
| `--config` | `-c` | path | None | 配置文件路径 |
| `--workspace` | `-w` | path | workspace | 工作区根目录 |
| `--max-retries` | | int | 3 | 最大重试次数 |
| `--no-human-review` | | flag | False | 跳过人工审查 |
| `--log-level` | | choice | INFO | DEBUG \| INFO \| WARNING \| ERROR |
| `--help` | `-h` | flag | - | 显示帮助信息 |

### 5.3 使用示例

```bash
# 基本使用
python3 orchestrator/main.py "Build a calculator"

# 带附件
python3 orchestrator/main.py "Implement the algorithm" -f paper.pdf

# 多个附件和URL
python3 orchestrator/main.py "Build a system" \
  -f design.pdf requirements.docx \
  -u https://example.com/doc1 https://example.com/doc2

# 仅研究
python3 orchestrator/main.py "What is Transformer?" -m research_only

# 自定义配置
python3 orchestrator/main.py "Build API" -c my_config.yaml

# 自定义工作区
python3 orchestrator/main.py "Build tool" -w /tmp/workspace

# 增加重试次数
python3 orchestrator/main.py "Complex task" --max-retries 5

# 自动模式（无人工审查）
python3 orchestrator/main.py "Simple task" --no-human-review

# 调试模式
python3 orchestrator/main.py "Debug task" --log-level DEBUG

# 查看帮助
python3 orchestrator/main.py --help
```

```bash
HTTP_PROXY=http://proxy.example.com:8080
HTTPS_PROXY=http://proxy.example.com:8080
```

```yaml
# config.yaml
orchestrator:
  max_retries: 3
  workspace_root: "./workspace"
  human_review: true

llm:
  provider: "openai"  # openai | modelscope | anthropic
  model: "gpt-4o"
  api_key: "${OPENAI_API_KEY}"
  temperature: 0.3
  max_tokens: 4096
  timeout: 300

research:
  mode: "auto"  # auto | deep | doc
  search_engines:
    - "arxiv"
    - "exa"
    - "serpapi"
  max_results: 10
  timeout: 600

spec:
  model: "gpt-4o"
  temperature: 0.3
  validation: true
  max_attempts: 3

test:
  model: "gpt-4o"
  temperature: 0.5
  include_fixtures: true
  include_mocks: true
  coverage_target: 0.80

code:
  model: "gpt-4o"
  temperature: 0.2
  timeout: 600
  verification: true

logging:
  level: "INFO"
  console: true
  file: true
  file_path: "logs/orchestrator.log"
```

## 7. 最佳实践

### 7.1 需求描述最佳实践

#### ✅ 好的需求描述

```bash
python3 orchestrator/main.py \
  "Build a REST API for blog management with these features:
   - CRUD operations for posts and comments
   - User authentication with JWT
   - Markdown support for post content
   - PostgreSQL database
   - FastAPI framework
   - Docker deployment support
   - Unit tests with pytest
   - API documentation with Swagger"
```

**特点**:
- 具体的功能需求
- 明确的技术栈
- 包含非功能需求（测试、部署）

#### ❌ 不好的需求描述

```bash
python3 orchestrator/main.py "Build a website"
```

**问题**:
- 过于模糊
- 缺少技术细节
- 容易产生误解

### 7.2 文件准备最佳实践

#### 7.2.1 文档格式

**推荐格式**:
- ✅ PDF - 最佳兼容性
- ✅ Markdown - 最佳解析效果
- ✅ DOCX - 良好支持
- 🟡 PPT - 部分支持
- 🟡 TXT - 基本支持

**准备建议**:
1. 确保文档结构清晰（有标题、章节）
2. 重要内容使用粗体或标题强调
3. 代码片段使用代码块格式
4. 图表清晰可读

#### 7.2.2 文件大小

| 文件大小 | 处理时间 | 建议 |
|---------|---------|------|
| < 1MB | < 1分钟 | ✅ 理想 |
| 1-5MB | 1-3分钟 | ✅ 可接受 |
| 5-10MB | 3-5分钟 | 🟡 较慢 |
| > 10MB | > 5分钟 | ❌ 建议拆分 |

### 7.3 成本优化

## 8. 常见问题FAQ

### 8.1 使用问题

#### Q1: 如何查看任务执行进度？

**答**: 查看日志文件

```bash
# 实时查看日志
tail -f workspace/run_xxx/logs/orchestrator.log

# 或使用log-level DEBUG
python3 orchestrator/main.py "query" --log-level DEBUG
```

#### Q2: 任务执行失败，如何恢复？

**答**: 当前版本不支持断点续传，但你可以：

```bash
# 1. 查看失败原因
cat workspace/run_xxx/logs/orchestrator.log | grep ERROR

# 2. 手动修复问题后继续
# 例如，如果Spec生成失败，可以手动创建tech_spec.md后重新运行

# 3. 未来版本将支持 --resume 选项
```

#### Q3: 如何修改生成的代码？

**答**: 直接编辑源文件

```bash
# 生成的代码在 workspace/run_xxx/src/
cd workspace/run_xxx/src
vim main.py

# 修改后重新运行测试
pytest ../tests/
```

### 8.2 性能问题

#### Q4: 任务执行太慢怎么办？

**答**: 优化策略

```bash
# 1. 使用更快的模型
MODEL_NAME=gpt-4o-mini

# 2. 减少搜索结果
MAX_SEARCH_RESULTS=5

# 3. 跳过人工审查
python3 orchestrator/main.py "query" --no-human-review

# 4. 使用本地缓存（未来支持）
```

#### Q5: 如何并行处理多个任务？

**答**: 使用多个终端或并行工具

```bash
# 方法1: 多个终端
# Terminal 1:
python3 orchestrator/main.py "Task 1" &

# Terminal 2:
python3 orchestrator/main.py "Task 2" &

# 方法2: GNU parallel
parallel -j 4 python3 orchestrator/main.py "{}" < tasks.txt
```

### 8.3 输出问题

#### Q6: 生成的代码不符合预期怎么办？

**答**: 调整需求描述或修改Spec

```bash
# 1. 重新运行，提供更详细的需求
python3 orchestrator/main.py \
  "Build a calculator with:
   - Support decimal numbers
   - Handle division by zero
   - Use Python Decimal for precision
   - Include docstrings
   - Follow PEP 8"

# 2. 或在Human Review阶段修改tech_spec.md
# 增加详细的实现要求
```

#### Q7: 测试失败后如何调试？

**答**: 查看错误信息

```bash
# 查看测试输出
cat workspace/run_xxx/logs/orchestrator.log | grep -A 10 "FAILED"

# 手动运行失败的测试
cd workspace/run_xxx
pytest tests/test_core.py::test_add -v

# 查看详细堆栈
pytest tests/test_core.py::test_add -vv
```

### 8.4 配置问题

#### Q8: API Key配置不生效？

**答**: 检查配置加载

```bash
# 检查环境变量
echo $OPENAI_API_KEY

# 手动加载.env
export $(cat .env | grep -v '^#' | xargs)

# 验证
python3 -c "import os; print(os.getenv('OPENAI_API_KEY'))"
```

#### Q9: 如何使用不同的模型？

**答**: 修改配置

```bash
# 方法1: 环境变量
export MODEL_NAME="claude-3-5-sonnet-20241022"

# 方法2: 配置文件
# 在 config.yaml 中设置
llm:
  model: "claude-3-5-sonnet-20241022"

# 方法3: 修改默认配置
# orchestrator/core/config.py
model_name: str = "gpt-4o"  # 改为其他模型
```

### 9.1 常见错误

#### 错误1: `ModuleNotFoundError: No module named 'ms_agent'`

**原因**: 依赖未安装

**解决**:
```bash
pip install -r requirements/framework.txt
```

#### 错误2: `ValueError: API Key is missing`

**原因**: API Key未配置

**解决**:
```bash
# 检查.env文件
cat .env | grep OPENAI_API_KEY

# 或直接设置
export OPENAI_API_KEY="sk-xxx"
```

#### 错误3: `Timeout: LLM request timed out`

**原因**: 网络问题或请求超时

**解决**:
```bash
# 增加超时时间
export LLM_TIMEOUT=600  # 默认300秒

# 或检查网络连接
curl -I https://api.openai.com

# 配置代理
export HTTP_PROXY=http://proxy.example.com:8080
```

#### 错误4: `FileNotFoundError: report.md not found`

**原因**: Research阶段失败

**解决**:
```bash
# 查看Research日志
cat workspace/run_xxx/logs/orchestrator.log | grep Research

# 检查网络和API Key
# 重新运行
```

## 10. 进阶使用

### 10.1 自定义Agent

```python
# custom_agent.py
from ms_agent.agent.llm_agent import LLMAgent

class MyCustomAgent(LLMAgent):
    def custom_logic(self, input_data):
        # 自定义逻辑
        response = self.run(
            messages=[{'role': 'user', 'content': input_data}]
        )
        return response
```

### 10.2 扩展Adapter

```python
# custom_adapter.py
from orchestrator.adapters.base import BaseAdapter

class CustomAdapter(BaseAdapter):
    def run(self, **kwargs):
        # 自定义实现
        return {
            'success': True,
            'output': 'Custom output'
        }
```

### 10.3 添加Hook

```python
# add_hooks.py
from orchestrator.core.hooks import HookRegistry

def my_post_spec_hook(spec_path):
    """自定义Spec后处理"""
    print(f"Spec generated at: {spec_path}")
    # 可以添加自动化检查
    content = spec_path.read_text()
    if 'security' not in content.lower():
        print("Warning: No security section in spec!")

# 注册Hook
HookRegistry.register('post_spec', my_post_spec_hook)
```
